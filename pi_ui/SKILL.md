# 界面验收

对本次界面自定义新增或修改做最终验收，发现漏图标、文字或控件错位、样式偏离及实际显示问题。开发保持轻量，验收按变化范围进行；不把验收扩展成重新设计。

## 先判断是否适用

**界面的自定义新增或修改必须审查，是否存在参考模板不是豁免条件。**

自定义变化包括新增设计的窗口、页面或控件，以及调整布局、排列、尺寸、间距、样式、字体、图标呈现、绘制逻辑或交互方式。无论用户指定还是开发过程中自行选择，无论是否复用已有控件、模板或设计稿，都须审查本次变化及受影响区域。微调也适用，但检查深度应与影响相称，不扩展为整套界面重审。

仅完整沿用模板设计、通过既定参数替换文字、数据或符合规范的图标内容，且没有改变设计规则时，走项目常规显示与功能验证，不启动本专项流程。若为内容适配调整布局、样式或交互，则调整部分必须审查。漏图标、错位等已发现问题仍需处理，不能以“有模板”免除修复。

模板与设计稿用于提供验收依据，而非决定是否审查。只查看用户资料、已有上下文、当前模块及相关公共控件，不进行无边界搜索，也不要求先创建模板或设计系统。

区分明确要求的设计变化与实现失误：前者按新设计检查，不因不同于旧模板就要求改回；后者按预期设计作为缺陷处理，不得包装成新设计。差异缺少依据或要求互相矛盾时，结合上下文确定预期，不能自行认可偏离。

## 判断执行时机

在本次约定交付范围实现完成、相关功能验证通过后，交付前集中执行。以可独立交付的部分为单位，不等待整个项目完成。

若提前调用，只确认适用范围及参照，继续原任务；不要启动完整清单或以反复调整外观代替功能实现。已有可操作性问题应及时解决。纯界面、原型或分阶段任务按约定目标验收，不补做范围外业务；模拟与占位须如实说明。

开发前的参照选择、复用及可选的修改前截图由原开发流程处理。最终验收不重跑开发流程；没有修改前截图时，依据需求、项目规范和实际运行结果检查，不要求重做开发。

## 执行验收

阅读 [验收清单](references/checklist.md)，只选择本次相关项目：新增或变更区域、直接受影响的相邻区域，以及共享实现的代表性使用位置。只验证项目支持且与变化相关的尺寸、内容、缩放和状态，不遍历全部组合。

依据顺序：用户明确要求、项目规范、同模块同用途控件、当前平台与主题的默认行为。依据这些规则及满足需求的设计选择检查，不以“代码就是这样写的”证明正确。只有影响实现且无法从上下文解决的冲突才澄清；常规取值不反复确认。

每个问题指出具体元素、违反依据及实际现象。无依据的审美偏好不阻塞验收；不照搬已知缺陷，也不扩展修复无关历史问题。

### 运行证据

- 具备条件时查看实际运行界面，确认加载了本次构建；也可采用可确认对应本次变化的运行截图。
- 检查整体上下文和局部细节；交互项必须有实际操作验证，静态截图不能证明交互正确。
- 源码、资源存在性、设计器预览及控件属性仅辅助判断，不能单独证明视觉通过。截图也须实际检查，保存图片本身不算验收。
- 对比尽量保持主题、字体、DPI、窗口尺寸和数据状态一致；测量统一坐标系及单位。不要求跨平台逐像素一致。
- 优先复用现有工具。无法运行、操作或获取必要证据时，完成能做的检查，记录限制、未验项及最小复验步骤，不盲调、不伪称通过。

## 结论、修复与停止

结论按以下顺序判断：

1. **未通过**：存在已确认、未解决的验收缺陷；同时列出未验证项，不得以环境受限掩盖已知失败。
2. **待验证**：没有已知未解决缺陷，但必要检查未完成。可交付待验证成果，不得宣称最终验收完成。
3. **通过**：适用检查完成且没有未解决的验收缺陷。结论仅覆盖实际验证范围。

如果任务要求实施或修复，在授权范围内修复具体问题；如果任务仅要求审查，报告发现，不自动修改代码。不得借验收擅自引入新设计体系或重构公共控件。

修复后只复验对应项目及可能受影响的区域；涉及事件、焦点、命中区域或状态逻辑时，补验相关功能。无新影响不重跑完整清单；通过后停止，不因主观“更美观”启动新一轮打磨。

不得删除检查、降低标准或直接更新截图基准掩盖失败。基准更新应对应明确的设计变化及项目既有流程。

同一问题反复修复无进展时停止重复盲调，整理复现条件和已排除原因，转向获取新证据。确实受阻则说明未完成项及下一步，不掩盖问题或转做无关美化。

## 与其他技能协作

- 本技能补充界面专项审查，不替代功能测试、代码审查和项目已有质量要求。
- 本技能的范围限制与停止条件仅约束本专项流程；专项通过不代表整个任务或其他检查已经通过。
- 复用此前对同一版本、环境和状态取得且仍有效的验证证据，只补查缺项与后续修改影响的部分，不因切换技能重复验证。
- 按实际技术栈使用其他技能，不将 Web 专属规则套用于 Qt/MFC。
- 无关历史问题单独报告，不擅自扩大修复范围；若其阻塞项目既有验收，应如实报告整体未通过。
- 不以本技能为由降低项目标准，也不默认叠加所有技能中与当前任务无关的检查。

## 简要交付

说明验收范围与依据、实际检查的环境和状态、可用证据位置、结论及未解决或未验证项。沿用项目报告形式，无须单独创建报告文件。编译或功能验证通过不等于视觉验收通过。
